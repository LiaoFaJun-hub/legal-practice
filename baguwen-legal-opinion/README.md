# 八股体法律意见书生成器 · baguwen-legal-opinion

> 以八股八段状态机约束法律推理，产出零跳跃、可回溯、三清单同屏的《法律分析意见书》。
> 内核是八股，外壳是律师文体——**八股是推理纪律，不是排版格式。**

## 这是什么

面向律师 / 法务 / 法律研究者的 AI 辅助分析技能。它不追求"更聪明的结论"，而是用结构
**强制打断** LLM 的流畅性本能（给确定答案 / 补全缺失 / 顺从提问 / 压缩步骤）——因为这四点恰是法律工作的敌人。

- **能力层级**：L2 八段 Workflow 骨架 + L4 局部对抗（第五/六股）+ 强制 HITL 出口
- **价值指标**：**执业者的人审复核耗时**与**结论可回溯性**，不是"结论正确率"

> 完整运行契约（十段式）见 [SKILL.md](SKILL.md)。

## 核心特性

| 特性 | 作用 |
|---|---|
| **前置澄清门（门0-A/0-B/0.5 + 门1/2）** | 门0-A 快照锁定决定性事实；门0-B 条件升档按要件深采；门0.5 补访环回问分析中缺口 |
| **要件定向采集（内化）** | 时间轴重建、证据载体六问、不利事实预问、目标底线——产出四件套直喂八段槽位 |
| **八段状态机** | 破题→承题→起讲→入手→起股→中股→后股→束股，不可跳过/合并/倒置 |
| **四态判定** | ✓成立 / ◐部分成立 / ✗不成立 / ?存疑——给模型合法的"不知道"出口 |
| **双轨制** | 推理轨（结构化、机器校验）→ 行文轨（律师文体、交付物） |
| **对抗隔离** | 第六股用子 Agent 隔离，只喂判定符号摘要，防锚定 |
| **fail-closed** | 无检索层时绝不回退模型记忆，法条一律标"待核验" |

## 快速开始（三种路径）

1. **全案生成**：喂案件事实与材料 →【门0-A 澄清（必要时经同意升门0-B 定向采集）】→ 跑全八段 → 出律师文体意见书。
   先读 [references/intake.md](references/intake.md)、[references/fact-elicitation.md](references/fact-elicitation.md) 与 [references/protocol.md](references/protocol.md)。
2. **审计已有分析**：粘贴一份法律分析 → 用元指令 LE 做幻觉与遗漏审计 → 按 P0/P1/P2 给出修正建议。
3. **单段深钻**：只深挖某一段（如第六股抗辩），见元指令 LC / LD。

## 前置澄清门（本技能的重点）

> 信条：**返工成本 > 问询成本**；但**问错、问浅、问脏，同样是返工之源**。

- **门0-A · 定向澄清（必做，开干前）**：问 ≤5 个"会使结论反转的关键事实"，必含**程序坐标**与**时效红线**两个强制项；每问过"五把筛子"（要件对应性/结论决定性/可核查性/来源可分级/不污染）、含"暂不清楚"选项；答后执行收口微仪式（复述确认＋"还有什么我没问到的"）。答不清楚的按**保守假设**推进并显式标注。环境无交互工具时，以文本列出问题并暂停。
- **门0-B · 定向采集（条件升档，经委托人同意）**：口头咨询主导 / ≥2 项"暂不清楚" / 高要件复杂度类型 / 单方陈述主导等触发；按九类框架 × T型漏斗 × 证据落地六问执行，产出**四件套**（程序信息表／事实时间线两栏／证据线索表／缺口归类），并通过收口自检＋三句话复述。
- **门0.5 · 补访环（第五段后，条件触发）**：判定出现 ？/◐ 且缺口属"可向当事人问出的事实"时，经同意定向回问；新事实**必须**回第三段重分层（零跳跃纪律不破），补访上限 2 轮。
- **门1（破题后，条件触发）**：候选争议 ≥2，或用户提问方向 ≠ 决定性问题时，回问确认焦点。
- **门2（入手后，条件触发）**：要件库未命中或属高风险场景时，确认要件框架。

门禁时序与触发矩阵见 [references/intake.md](references/intake.md)；采集工艺（问什么/怎么问/怎么收口）见 [references/fact-elicitation.md](references/fact-elicitation.md)。

## 校验脚本

```bash
python scripts/check_redlines.py <推理轨文件>    # R1-R4 + 绝对化词 + S→F + 结论条件化 + 禁确定数值
python scripts/check_dod.py <推理轨文件>          # 逐段 DoD 门禁（含澄清/假设登记、门0-B 四件套、补访重分层弱校验，opt-in）
python scripts/validate_delivery.py <行文轨文件>  # 内容完整性 + 文体合规 + 三清单同屏
```

输出 `P0/P1/P2` JSON 报告；存在 P0 时退出码为 1。
> 注：【仅用户提供模式】下 `check_redlines` 会稳定报 1 条 `R1-占位`（P1），属预期，非缺陷。
> 注：门0-B 四件套与补访重分层为 **opt-in** 弱校验——仅当推理轨标记"定向采集"/"补访记录"时启用，未升档旧轨免检。

## 模式与场景

- **全八段**：内部研究备忘、诉讼策略、合规审查、需留痕可回溯的分析。
- **精简三段**：普法 / 知识问答（仅保留破题 + 承题 + 束股）。
- **场景特化**：合同审查（第四股改为"条款风险清单遍历"）、类案检索、证据梳理。
- **采集分档**：门0-A 快照（默认）／门0-B 深采（条件升档，经同意）／门0.5 补访（分析中回环）。

五个不可用 / 慎用地带（刑事定罪、胜诉率预测、凭记忆出条文等）见 [references/scenario-fit.md](references/scenario-fit.md)。
