# 八股体法律意见书生成器

> **设计哲学**：内核是八股，外壳是律师文体。八股是推理纪律，不是排版格式——用结构强制打断 LLM 的流畅性本能（给确定答案 / 补全缺失 / 顺从提问 / 压缩步骤），因为这四点恰是法律工作的敌人。
>
> **核心红线速览**：R1 法条来源（禁凭记忆出条文，必须检索回填或用户提供）· R2 要件覆盖（第五股判定集合 == 第四股要件集合）· R3 对抗隔离（第六股子 Agent 隔离，只收判定符号摘要）· R4 留痕同屏（存疑/边界/排除三清单与结论同屏）。

一句话职责：以八段状态机约束模型推理，产出零跳跃、可回溯、三清单同屏的《法律分析意见书》。能力层级 = L2 八段 Workflow 骨架 + L4 局部对抗（第五/六股）+ 强制 HITL 出口。**价值指标是执业者的人审复核耗时与结论可回溯性，不是"结论正确率"。**

## 触发词

**正向触发**（满足其一即加载）：
- 「按八股写法律意见书」「八股体意见书」「用八股范式分析法律问题」
- 「法律意见书」「案件分析意见」「诉讼策略分析」「合规审查意见」且要求严谨可复核
- 「零跳跃推理」「防要件遗漏」「对抗式法律分析」「法律幻觉核验」
- 对已有法律分析做「幻觉审计」「要件覆盖检查」「八股审计」

**排除（不触发本技能）**：
- 普法 / 知识问答 → 走本技能"精简三段"模式
- 合同条款比对 → `contract-diff`
- 纯法条检索 / 类案检索 → `legal-research-analyst`
- 文书格式化 / 排版转换 → `legal-text-format`

## 调用者

- **主控 Agent**：当用户直接提出法律分析/意见书类请求，且需严谨可复核时加载本技能。
- **不调用场景**：简单事实查询、格式转换、纯检索——这些由更轻的技能或直答处理。
- **无强制上游**：本技能可独立运行；不依赖任何 Agent 编排即用。

## SOP 总览

```
① 分诊定档 + 门0 前置澄清 ──→ ② 破题…入手（门1/门2）──→ ③ 起股 + 中股(子Agent隔离)
        ▲                                                          │
        │                                                          ▼
   假设声明/模式                                         ④ 后股权衡 + 束股收敛
        │                                                          │
        └──────────── 校验 lane（P0 回退）◄─────────────────────────┘
                                   │
                    ⑤ 校验(推理轨) ──→ ⑥ 行文改写 + 交付校验(行文轨)
```

- **数据传递**：门0 的假设声明 → 第三段 U 类 → 第八段存疑清单 → 行文轨开头；段间以"交接包"传递（结构化对象，含清单与判定结果）。
- **判断分支**：门1/门2 条件触发；校验 P0 回退（上限 2 次转人工）。
- **双轨制**：推理轨（结构化、机器校验）→ 行文轨（律师文体、交付物）。校验压推理轨，成品做行文轨。

## 输入

| 字段 | 必需/可选 | 说明 |
|---|---|---|
| 案件事实 / 材料 | 必需 | 用户叙述、合同、通知、凭证等；可仅有口头咨询 |
| 咨询范围 / 偏好 | 可选 | 关注点、法域、时点、篇幅 |
| 检索层 | 可选 | 有法律检索 MCP 则走【全检索模式】；无则走【仅用户提供模式】 |

## 输出

| 输出物 | 格式 | 说明 |
|---|---|---|
| 推理轨 | Markdown（含第零段+八段） | 结构化，供脚本校验；含四态符号与编号 |
| 行文轨 | 律师文体《法律分析意见书》 | 八章 + 附录一引用索引/附录二人审清单/附录三自检表 |
| 校验报告 | JSON（P0/P1/P2） | 三个脚本的输出 |

## 详细操作步骤

> 引用文件均在技能目录下；`references/` 存放知识与条件性文档，`templates/` 存放产出模板，`scripts/` 存放确定性校验。

### 步骤 1 · 分诊定档 + 门0 前置澄清

- **目标**：确定模式（全八段/精简三段/场景特化），并锁定会使结论反转的决定性事实，避免全篇返工。
- **动作**：读 [references/scenario-fit.md](references/scenario-fit.md) 定档；执行 [references/intake.md](references/intake.md) 门0：先对用户**说明目的**，再用 AskUserQuestion 提 ≤5 问（每问必含"暂不清楚"选项）。
- **判断逻辑**：**如果** 环境无交互提问工具，**则** 以文本列出问题并暂停（禁止跳过门0硬跑）；**如果** 用户答"暂不清楚"，**则** 登记假设声明，按**保守假设**（非对用户有利）推进。
- **交付**：第零段·澄清（问题 / 用户回答 / 假设声明）。
- **质量检查点**：目的已说明；每问含"暂不清楚"；假设已登记。

### 步骤 2 · 破题至入手（含门1 / 门2）

- **目标**：锚定争议、分层事实、建立**封闭**要件清单。
- **动作**：按 [references/stage-rules.md](references/stage-rules.md) 依次执行第一段破题→第四段入手；框架取自 [references/element-library.md](references/element-library.md)；无检索层时读 [references/retrieval-adapter.md](references/retrieval-adapter.md) 走【仅用户提供模式】。
- **判断逻辑**：**如果** 候选争议 ≥2 或用户提问方向 ≠ 决定性问题，**则** 触发门1回问确认；**如果** 要件库未命中或属高风险场景，**则** 触发门2确认要件框架。
- **交付**：交接包 ①–④。
- **质量检查点**：破题/承题/起讲/入手 四段 DoD 全部通过（见 stage-rules.md）。

### 步骤 3 · 起股正向论证 + 中股隔离抗辩

- **目标**：逐要件四态判定；从相对方视角穷尽抗辩。
- **动作**：第五段按 A1..An 逐项四态判定（✓◐✗?）并做覆盖自检；**必须** 用**子 Agent 隔离**执行第六段，仅喂「分层事实表 + 要件清单 + 法条锚点 + 判定符号摘要」，**不得**喂第五段推理文本（R3）。
- **工具**：Task 子 Agent；[references/redlines.md](references/redlines.md) 抗辩穷尽树。
- **判断逻辑**：**如果** 第五段存在 ✓成立，**则** 第六段须对每个 ✓ 至少攻击一次；**如果** 某类抗辩无内容，**则** 显式写"经检索未发现可行抗辩事由"，不得留空。
- **交付**：交接包 ⑤⑥。
- **质量检查点**：判定集合 == 要件集合（R2）；五类抗辩齐；漏洞清单 ≥2。

### 步骤 4 · 后股权衡 + 束股收敛

- **目标**：对冲突点做有依据的权重判定，并强制显性留痕。
- **动作**：第七段逐冲突点填天平五项并走完 7 条优先级规则、写明命中编号；第八段输出条件式结论 + 存疑/适用边界/排除三清单同屏（R4）。
- **判断逻辑**：**如果** 冲突点无法排除，**则** 判"存疑"并写明缺口，**不得**强行消除；**如果** 结论无法条件化，**则** 回退第七段补充权衡。
- **交付**：交接包 ⑦ + 完整八段推理轨。
- **质量检查点**：束股 DoD；结论含"倾向于"与"若…则"。

### 步骤 5 · 校验（推理轨）

- **目标**：自动拦截结构性缺陷。
- **动作**：
  ```
  python scripts/check_redlines.py <推理轨文件>
  python scripts/check_dod.py <推理轨文件>
  ```
- **判断逻辑**：**如果** 出现 P0，**则** 回退对应段重跑（上限 2 次）；**如果** 回退超限，**则** 转人工并显式说明"本段未能完成"。
- **交付**：校验报告（P0/P1/P2）。
- **质量检查点**：P0 = 0（【仅用户提供模式】下 `R1-占位` 的 1 条 P1 属预期，非缺陷）。

### 步骤 6 · 行文改写 + 交付校验

- **目标**：把推理轨改写为"律师真实在写"的文书，并保证内容不缩水。
- **动作**：按 [references/writing-style.md](references/writing-style.md) 与 [templates/opinion-template.md](templates/opinion-template.md) 改写；机械符号不外泄正文；再运行：
  ```
  python scripts/validate_delivery.py <行文轨文件>
  ```
- **判断逻辑**：**如果** 正文出现 `A1` / `✓` / `C1` 等机械符号或半角 `?`，**则** 改为文字表达或全角"？"；**如果** 校验 P0 > 0，**则** 修正后重跑。
- **交付**：律师文体《法律分析意见书》（八章 + 三附录），可套用 [templates/opinion-prose-example.md](templates/opinion-prose-example.md) 锚定语感。
- **质量检查点**：三清单同屏；三附录齐；引用可溯源。

## 错误处理

| 异常 | 检测方式 | 处理策略 | 严重性 |
|---|---|---|---|
| 无交互提问工具（门0） | 环境探测 | 文本列出问题并暂停，等回复再开干 | 阻断（不跳过门0） |
| 检索层不可用 | MCP 探测失败 | 切【仅用户提供模式】，法条标"未检索到/待核验"，**禁**回退模型记忆 | 降级 |
| 要件库未命中 | element-library 未命中 | 由法条反推要件，并在存疑清单登记"框架未经要件库校验" | 降级 |
| 校验出现 P0 | 脚本输出 | 回退对应段重跑，上限 2 次后转人工 | 阻断 |
| 校验 P1（fail-closed 占位） | 脚本输出 | 记录并如实标注，不作阻断 | 降级 |
| 推理轨缺失某段 | check_dod 报"存在性" P0 | 补做该段后重跑 | 阻断 |

## Gotcha清单

以下均为本技能构建与实测中真实翻车过的点，每条附 Why：

1. **判定行分行会导致 R2 误报。** 模板把 `A1` 与"判定：✓"分两行，早期脚本要求同行 → 误报"要件集合不一致"（P0）。**Why**：脚本已改为按 A-块识别（`a_state_ids`），但写推理轨时四态符号仍须与该要件 A 编号**同块**，勿隔多段。
2. **门0 提问编号勿用 `Q`。** 第八段存疑清单也用 `Q1..Qn`，同轨内 `Q` 语义冲突。**Why**：门0 提问一律用"问1..问n"，与存疑 Q 区隔。
3. **fail-closed 下 `R1-占位` P1 恒存，属预期。** 【仅用户提供模式】永远不可能全绿（必红 1 条 P1）。**Why**：这是"无检索层接入"的正常表现，不得据此判交付不合格；交付说明应如实标注未核验。
4. **半角 `?` 是机械符号。** 四态符号之一，正文用全角"？"。**Why**：`validate_delivery` 会把半角 `?` 判为机械符号外泄（P0）。
5. **分段切分依赖段标题格式。** 推理轨段标题用"## 第N段 · 名"。**Why**：`split_sections` 优先按"行首 第N段/股"切，若第零段无意出现"入手/承题"等八股名会造成错切。
6. **模板与脚本契约必须同步。** 改 `templates/*` 或 `scripts/*` 任一方，须回归另一方。**Why**：实测中"模板分行 / 脚本要求同行"的不一致会让正常产出误报 P0。
7. **绝不因无 MCP 而凭记忆出条文。** 宁可输出"未检索到"。**Why**：接 MCP 反制造"有检索就敢编"的假象，比不接更危险。

## 协作技能

| 协作技能 | 用途 | 调用时机 |
|---|---|---|
| `contract-diff` | 合同条款差异比对 | 请求为合同比对时，**转出**本技能 |
| `legal-research-analyst` | 纯法条/类案检索 | 请求为检索而非分析时，**转出** |
| `legal-text-format` | 法律文本格式化 | 请求为排版转换时，**转出** |
| `legal-opinion-generator` | 通用法律意见书（流派路线） | 用户不需八股协议时可用；本技能是其八股增强变体 |
| `legal-proposal-generator` | 多类法律服务文档 | 需生成咨询报告/方案等非意见书时 |

> 本技能**不强制**调用其他技能；上表主要用于**调用边界判定与转出**。

## 经验沉淀

- 每次执行后，把新发现的翻车点 / 边界案例**追加**（append-only）到 [references/experience-log.md](references/experience-log.md)，不覆盖历史。
- 同一类翻车累积 ≥2 次 → 升格为正文 Gotcha 清单的一条。
- **Why**：本技能随使用变强——有经验时 2–3 步定位，无经验时需 10+ 步试错。

## 铁律

**MUST**
- 开干前**必须**过门0：先说明目的、再提 ≤5 问、登记假设。
- 第六股**必须**用子 Agent 隔离（R3）；第五股**必须**全要件遍历（R2）。
- 三清单**必须**与结论同屏（R4）；结论**必须**条件式。
- 法条引用**必须**四元组回填或显式标"待核验"（R1）。

**MUST NOT**
- 禁止凭模型记忆输出条文号或原文。
- 禁止把单方陈述(S)当作已证事实(F)支撑"成立"判定。
- 禁止给无条件结论或确定数值（胜诉率、赔偿额）。
- 禁止把机械符号（`A1`/`✓`/`C1`/半角`?`）外泄到行文轨正文。

**SHOULD**
- 应优先用现有脚本校验，而非目测。
- 应在信息不足时显式标注"存疑/假设"，而非编造。
