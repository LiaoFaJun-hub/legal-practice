# 前置澄清与确认门（防返工）

> 核心信条：**返工成本 > 问询成本**。开干前问 3–5 个问题用 1 分钟，
> 胜过八段全篇建立在错误前提上再返工。
> 本文件是运行时**门禁**，不是推理段。门未过，不得进入下一阶段。

## 0. 三道门总览

```
输入 → 分诊定档
   → 【门0 · 前置澄清】必做（全八段模式）        ★开干前
   → 第一段 破题
   → 【门1 · 焦点确认】条件触发                  ★破题后
   → 第二段…第八段
   → 【门2 · 要件框架确认】条件触发 / 高风险       ★入手后（可选）
   → 校验 → 行文 → 交付
```

| 门 | 时机 | 触发 | 目的 |
|---|---|---|---|
| **门0** | 开干前 | **必做**（精简三段模式可简化为一问或跳过） | 锁定会使结论反转的决定性事实 |
| **门1** | 破题后 | 候选争议 ≥2，或用户提问方向 ≠ 决定性问题 | 确认争议焦点，防框架错配 |
| **门2** | 入手后 | 要件库未命中（框架由模型推导）**或** 高风险场景 | 防"要件框架错"导致全章返工 |

---

## 1. 门0 · 前置澄清

### 目的（须对用户显式说明）
> 为避免全篇返工，先确认 N 项会使结论反转的关键事实。若某项不清楚，可选择"暂不清楚"，
> 我会按保守假设推进并显式标注——这样不会耽误您，也不会让结论建立在未声明的前提上。

### 问题设计原则

**问什么**：只问"会使结论反转的决定性事实"，分三类优先顺序——

```
① 定性事实：法律关系性质与效力（是否生效？属 A 还是 B？）
② 范围事实：争讼标的范围（有无标的、资产、子女、争议范围）
③ 程序事实：程序阶段与期限（是否已进入程序、有无临界期限）
```

**怎么问**：
- 问题数 **≤5**；每个问题 header ≤30 字；选项 2–4 个具体项（工具自动附"自定义"）。
- **每问必须含一个末选项**："暂不清楚 / 按保守假设继续"。
- 问题应**直接映射到会使结论反转的要件**（可据 [element-library.md](element-library.md) 的要件反推：
  "哪个要件一旦不成立，全案结论翻转？"→ 那个要件对应的事实就是要问的）。
- 一次问完，不要分段反复打扰。

### 依回答处置

```
材料充分 → 直接开干
含"暂不清楚" → 登记【假设声明】：
    "用户未确认事实 → 按最不利/保守假设推进"，并列入：
      · 第三段 U 类（存疑事实）
      · 第八段存疑清单
      · 行文轨开头的"假设声明"位
    禁止默认按对用户有利的假设推进
```

### 运行环境降级
若运行环境**未提供 AskUserQuestion（或等价交互提问工具）**：
以文本列出问题清单并**暂停**，等用户回复后再开干；不得跳过门0硬跑。

> 测试/harness 约定：若为自动化测试或批量运行，可在文本列出问题后**以预设的模拟回答续跑**，
> 但必须在第零段显式标注"以下回答为模拟输入"；不得把模拟回答伪装为用户真实确认。

### 输出形态（写入推理轨"第零段 · 澄清"）

```
第零段 · 澄清
[目的说明]：为避免全篇返工，先确认 N 项关键事实。若无把握可选"暂不清楚"。
问1 ____________________
   用户回答：____
问2 ____________________
   用户回答：____
[假设声明]：用户对 问_ 未确认 → 本案按假设 H1（____）推进；若实际不同，结论将改变。
```

> ★ 编号用「问」而不用「Q」，以避开第八段存疑清单的 `Q1..Qn`（同一推理轨中语义不混淆）。

## 2. 门1 · 焦点确认（破题后）

### 触发条件（满足其一即触发）
- 破题产出 **≥2 个候选争议**；
- **用户提问方向 ≠ 决定性问题**（如用户问"扣发是否合法"，而决定性问题其实是"赔偿义务是否成立"）。

### 动作
向用户呈现核心争议与决定性问题，确认后再进入第二段。格式：
> 本所理解的核心争议是【X】；其中决定性问题为【Y】，可能与您提问的方向【Z】不一致。
> 请确认按何者展开：① 按 X/Y　② 按您的原问题　③ 两者并列审视。

> 这一条本是破题段的既有规则，此前常被跳过；现升级为**门禁**：未过门1，破题段 DoD 不通过。

---

## 3. 门2 · 要件框架确认（入手后，可选/条件触发）

### 触发条件
- 要件库**未命中**，要件框架系由法条反推（模型推导）；
- 或属**高风险场景**（人身自由、重大财产、刑事相关）。

### 动作
把第四段的**要件清单**呈现给用户/执业者确认，并明示其来源（要件库 / 模型推导）。
> 防的是最贵的一类错误：**要件框架错 → 全篇"没说到" → 整章返工**。
> 若用户不便确认，则在存疑清单登记"要件框架未经校验"并继续。

---

## 4. 与其它段的衔接

- 门0 的"暂不清楚"项 → 直接映射为第三段 U 类与第八段存疑清单，**不重复登记**。
- 门0 的假设声明 → 在行文轨开头"材料来源声明"处对应声明"本分析基于假设 H1…"。
- 门1/门2 的确认结果 → 作为破题/入手两段的 DoD 通过依据，写入交接包。

---

## 5. 案例：若在"婚姻撤销"案执行门0

> 咨询："婚姻被撤销后，财产和子女怎么处理？"

**目的说明 + 门0 提问**（示例）：

```
为避免全篇返工，先确认以下 5 项会使结论反转的关键事实；若无把握，可选"暂不清楚"，
我会按保守假设推进并显式标注。

问1 该婚姻是如何被"撤销"的？
   A 法院判决撤销  B 婚姻登记机关撤销  C 尚在撤销诉讼中  D 暂不清楚
   （决定：撤销是否已生效、属"撤销"还是"无效"——影响全案前提）

问2 撤销所依据的事由？
   A 胁迫  B 一方隐瞒重大疾病  C 其他/不清楚  D 暂不清楚
   （决定：撤销权除斥期间起算与是否合法定事由）

问3 目前需处理的财产范围？
   A 有明确的共同财产  B 有争议但范围不明  C 无可处理财产  D 暂不清楚

问4 是否涉及子女？
   A 有未成年子女  B 有成年子女  C 无子女  D 暂不清楚

问5 是否已进入或准备进入诉讼？
   A 已起诉  B 准备起诉  C 仅咨询  D 暂不清楚
   （决定：程序路径与是否可一并处理）
```

**处置**：若 问1 答 D → 登记假设 H1"婚姻撤销情形不明，暂按'已依法撤销且生效'的框架展开方向性分析"，
并在开头声明；这样读者一开始就知道分析建立在什么前提上，**而非读到最后才发现**。
