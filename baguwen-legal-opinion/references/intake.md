# 前置澄清与确认门（防返工）

> 核心信条：**返工成本 > 问询成本**。开干前问对问题，胜过八段全篇建立在错误前提上再返工。
> 但问询本身也有成本：**问错、问浅、问脏，同样是返工之源**。故门0 分两相——A 相管"快"（决定性事实快照），B 相管"深"（按要件定向采集），门0.5 补访环管"回"（分析中缺口回问）。
> 本文件是运行时**门禁**，不是推理段。门未过，不得进入下一阶段。
> 采集工艺（问什么/怎么问/怎么收口）的完整协议见 [fact-elicitation.md](fact-elicitation.md)；本文件只管**门禁时序与触发**。

## 0. 门禁总览

```
输入 → 分诊定档（scenario-fit：含采集分档）
   → 【门0-A · 定向澄清】必做（默认档）                 ★开干前
   → 【门0-B · 定向采集】条件升档（触发＋委托人同意）    ★读 fact-elicitation.md
   → 第一段 破题
   → 【门1 · 焦点确认】条件触发                          ★破题后
   → 第二段…第五段
   → 【门0.5 · 补访环】条件触发（第五段事实缺口，经同意） ★读 fact-elicitation.md
   → 【门2 · 要件确认】条件触发                          ★入手后
   → 第六段…第八段 → 校验 → 行文 → 交付
```

| 门 | 时机 | 触发 | 目的 |
|---|---|---|---|
| **门0-A** | 开干前 | **必做**（精简三段模式可简化为一问） | 快照锁定会使结论反转的决定性事实（≤5 问，必含程序坐标与时效红线） |
| **门0-B** | 门0-A 后 | 条件触发（见 §2）＋委托人同意 | 按要件定向采集：时间轴、证据载体、不利事实、目标底线——产出四件套 |
| **门0.5** | 第五段后 | 第五段 ？/◐ 且缺口属"可问出的事实"；经同意 | 分析中回问补事实；新事实**必须**回第三段重分层 |
| **门1** | 破题后 | 候选争议 ≥2，或提问方向 ≠ 决定性问题 | 确认争议焦点，防框架错配 |
| **门2** | 入手后 | 要件库未命中（框架由模型推导）或高风险场景 | 防"要件框架错 → 全篇没说到 → 整章返工" |

## 1. 门0-A · 定向澄清（默认档，必做）

### 目的（须对用户显式说明）
> 为避免全篇返工，先确认 N 项会使结论反转的关键事实。若某项不清楚，可选择"暂不清楚"，我会按保守假设推进并显式标注——这样不会耽误您，也不会让结论建立在未声明的前提上。

### 问题设计原则

**必含强制项（与案情无关，每案必问；实案教训：漏问即执业事故）**：
- **程序坐标**：当前所处阶段（未诉/一审/二审/执行等）、已生效文书/前案裁决、有无前任律师及更换原因；
- **时效与期限红线**：时效/除斥期间/上诉期/举证期限的**最近届满日**——错过即失权，一票否决。

**决定性问题选入（≤5 问总额含强制项）**：
- 只问"会使结论反转的决定性事实"，优先顺序：① 定性事实 ② 范围事实 ③ 程序事实；
- 每问入清单前过**五把筛子**（见 [fact-elicitation.md](fact-elicitation.md) §三）：要件对应性 / 结论决定性 / 可核查性 / 来源可分级 / 不污染；
- header ≤30 字；选项 2–4 个具体项（工具自动附"自定义"）；**每问必含末选项**"暂不清楚 / 按保守假设继续"；
- **三种禁止问法**：不打断完整叙事、不双捆（一句话两个问题）、不用"为什么"主追（改"当时是什么情况让你决定……"）；
- 一次问完，不分段反复打扰。

### 收口微仪式（答后执行，成本约三句话）
1. **复述确认**：把答复复述为一段理解，请用户确认（"我按这样理解对吗"）；
2. **补一问**："还有什么你觉得关键、但我没问到的？"——不问，他日后就可以说"是你没问"。

### 依回答处置

```
材料充分 → 直接开干
含"暂不清楚" → 登记【假设声明】：
    "用户未确认事实 → 按最不利/保守假设推进"，并列入：
      · 第三段 U 类（存疑事实）
      · 第八段存疑清单
      · 行文轨开头"假设声明"位
    禁止默认按对用户有利的假设推进
触发门0-B 升档条件（≥2 项"暂不清楚"／口头咨询主导／高要件复杂度／单方陈述主导／用户要求）
    → 先征得同意，再进入门0-B
```

### 运行环境降级
若运行环境**未提供 AskUserQuestion（或等价交互提问工具）**：以文本列出问题清单并**暂停**，等用户回复后再开干；不得跳过门0硬跑。
测试/harness 约定：可为自动化测试以预设模拟回答续跑，但必须在第零段显式标注"以下回答为模拟输入"。

### 输出形态（写入推理轨"第零段 · 澄清"）
问n 编号（★ 用「问」而不用「Q」，以避开第八段存疑清单的 Q 语义），格式见 [templates/stage-outputs.md](../templates/stage-outputs.md)。

## 2. 门0-B · 定向采集（条件升档）

### 触发条件（满足其一）＋ **委托人同意**
1. 咨询以口头为主、无成套文书；
2. 门0-A 回答中 ≥2 项"暂不清楚"；
3. 争议属高要件复杂度类型（婚姻家事涉财产抚养／建设工程／股权／多主体）；
4. 材料虽多但来源单一、无第三方载体（单方陈述主导）；
5. 委托人明确要求深度采集。

**同意话术**："案情需要一轮定向采集——按法律要件逐项核对事实与证据载体，约多花几分钟，可否？"

### 执行
读 [fact-elicitation.md](fact-elicitation.md) 全文，按其协议执行：
- **问什么**：九类采集框架 × 八股槽位映射（§二）——程序坐标 → 目标底线 → 主体关系 → 时间轴 → 行为合意 → 金钱损失 → 证据载体 → **不利事实与对方抗辩** → 约束条件；
- **怎么问**：T 型漏斗四段（开场开放 → 主题收窄＋复述确认 → 矛盾核对 → "还有什么我没问到的"）× 状态自适应（展开/打捞/回追/卸下）× 四条追问铁律（数字/载体/未定义词/缝隙）；
- **证据落地**：每个成形断言追六问（载体/位置/持有人/可取得性/孤证/反证），落地状态四档直写第三段 U 表。

### 交付四件套（写入第零段）
1. **程序信息表**：阶段／期限与届满日（尤其时效）／已生效文书／待办节点；
2. **事实时间线**（两栏）：当事人陈述｜已验证来源——不得混列；
3. **证据线索表**：断言｜载体｜持有人｜取得路径｜灭失风险｜落地状态；
4. **缺口归类清单**：法律争点／事实争点／证据争点。

**收口 DoD**＝收口自检五条＋三句话复述（fact-elicitation.md §六）。说不出三句话 → 不得开干，回到漏斗继续采。

### 降级
时间预算极短（如一通电话）：明说产出上限——只采事件骨架（骨架层三问：谁对谁做了什么／有没有约定过／钱物话有没有给出去），声明"本次只拿到准备好的版本"，验收标准换成"事件骨架完整"，结束时回到要件清单再约第二次。

## 3. 门0.5 · 补访环（分析中回问）

### 触发条件（满足其一）
- 第五段判定出现 ？/◐，且缺口属**可向当事人问出的事实**（四要素类、载体类），而非纯客观调取类（纯调取走第八段补强建议）；
- 门1 / 门2 确认过程中发现事实缺口；
- 校验 P0 回退归因于事实性缺口。

### 动作

```
1. 列缺口清单：每项标【缺什么事实 → 对应要件 A_ → 拟提问题】
2. 经委托人同意 → 定向补问（T漏斗中段工艺：先开放后收窄＋复述确认＋载体六问）
3. 补访记录写回第零段【补访记录】位（轮次／问题／新事实）
4. ★新事实必须回第三段重新过四态分层——禁止直接改第五段判定（零跳跃纪律不变）
5. 第五段判定更新 → 重跑校验
```

### 纪律
- 补访上限 **2 轮**；超限转人工，或按保守假设登记后推进；
- 不得借补访教当事人怎么说、统一口径（伦理红线，详见原技能 references/04）；
- 委托人不同意补访 → 缺口按现行规则处理：标存疑＋保守假设＋第八段补强建议列出待采清单（用户可交付后自行采集）。

## 4. 门1 · 焦点确认（破题后）

### 触发条件（满足其一即触发）
- 破题产出 **≥2 个候选争议**；
- **用户提问方向 ≠ 决定性问题**（如用户问"扣发是否合法"，而决定性问题其实是"赔偿义务是否成立"）。

### 动作
向用户呈现核心争议与决定性问题，确认后再进入第二段。格式：
> 本所理解的核心争议是【X】；其中决定性问题为【Y】，可能与您提问的方向【Z】不一致。
> 请确认按何者展开：① 按 X/Y　② 按您的原问题　③ 两者并列审视。

> 这一条本是破题段的既有规则，此前常被跳过；现升级为**门禁**：未过门1，破题段 DoD 不通过。

---

## 5. 门2 · 要件框架确认（入手后，可选/条件触发）

### 触发条件
- 要件库**未命中**，要件框架系由法条反推（模型推导）；
- 或属**高风险场景**（人身自由、重大财产、刑事相关）。

### 动作
把第四段的**要件清单**呈现给用户/执业者确认，并明示其来源（要件库 / 模型推导）。
> 防的是最贵的一类错误：**要件框架错 → 全篇"没说到" → 整章返工**。
> 若用户不便确认，则在存疑清单登记"要件框架未经校验"并继续。
> 确认中发现"需问当事人才能定的事实"（如要件对应的关键事实完全空白）→ 可走门0.5 补访环定向回问，再回填第四段映射。

---

## 6. 与其它段的衔接

- 门0-A 的"暂不清楚"项 → 直接映射为第三段 U 类与第八段存疑清单，**不重复登记**；
- 门0-B 四件套 → 第零段＋第三段预填：时间线两栏即 F/S 预分层，证据线索表即 U 表"转为已证所需证据"预填，缺口归类清单即第六段抗辩预置的输入；
- 门0.5 补访记录 → 第零段【补访记录】位；新事实一律经第三段重分层进入，判定随后更新；
- 门0 假设声明 → 行文轨开头"材料来源声明/假设声明"位对应声明；
- 门1 / 门2 的确认结果 → 作为破题/入手两段的 DoD 通过依据，写入交接包。

## 7. 案例：婚姻撤销案的门0

> 咨询："婚姻被撤销后，财产和子女怎么处理？"

**门0-A（快照版）**：

```
为避免全篇返工，先确认以下关键事实；若无把握，可选"暂不清楚"，我会按保守假设推进并显式标注。

问1 程序坐标（强制项）：该婚姻如何被"撤销"？现处于什么状态？
   A 法院判决撤销  B 婚姻登记机关撤销  C 尚在撤销诉讼中  D 暂不清楚
问2 时效红线（强制项）：有无正在进行的期限（撤销权除斥期间/上诉期/举证期）？
   A 有，即将届满  B 有，尚充裕  C 无  D 暂不清楚
问3 撤销所依据的事由？
   A 胁迫  B 一方隐瞒重大疾病  C 其他/不清楚  D 暂不清楚
问4 需处理的财产与子女范围？
   A 有明确共同财产＋未成年子女  B 范围不明  C 无  D 暂不清楚
```

**处置**：若 问1、问3 均答 D（≥2 项"暂不清楚"）且系口头咨询 → 触发门0-B 升档征询；若用户同意，则按 fact-elicitation.md 走完整漏斗（时间轴重建 → 载体六问 → 不利事实预问 → 目标底线），产出四件套后再开干。若用户答 A＋B 且材料齐备 → 直接开干，按假设 H1 无需登记。
