# 红线、幻觉闸与结构化规则表

> 本文件是自动校验的**依据**：脚本按本文件的约定解析推理轨输出。
> 推理轨使用严格标记；行文轨不使用（改由附录承载）。

## 一、四条工程红线

```
R1【法条来源红线】输出中每一处条文号与原文必须由检索层回填或用户提供。
   检测到"凭记忆输出条文"→ 该段判定失败并重跑。
   实现：引用模板强制四元组 [条文号][原文片段][来源标识][效力核验时间]。

R2【要件覆盖红线】第五股判定条目集合必须 == 第四股要件清单集合（非仅计数）。
   不等 → 门禁拦截。这是防遗漏最有效的单一机制。

R3【对抗隔离红线】第六股子 Agent 上下文中不得包含第五股完整论证文本，
   只可接收「要件框架 + 分层事实 + 正向判定符号摘要」。
   目的：防抗辩被正向论证措辞锚定（锚定效应）。

R4【留痕同屏红线】存疑清单、排除项清单、适用边界清单必须与最终结论在同一屏输出，
   禁止折叠进脚注/附录/展开区。三清单缺一即判定交付不合格。
```

## 二、五道幻觉防御闸

```
闸① 生成前 · 来源锁定
    法条原文由检索层提供并注入上下文；系统指令明确"不得凭记忆输出条文"；
    未命中 → 输出"本项规范未检索到，需人工核实"。

闸② 生成中 · 引用槽位强制
    输出模板强制四元组 [条文号][原文片段][来源标识][效力核验时间]；
    缺失任一元素 → 格式校验失败，本段重跑。

闸③ 生成后 · 存在性校验
    每个引用回法条库精确比对（条文号匹配 + 原文子串匹配）；
    不匹配 → 剔除该引用并在存疑清单登记。
    （有 MCP 时可用 pkulaw_cite / pku_citation_validator 外部化。）

闸④ 生成后 · 时效与管辖校验
    条文当前效力状态？是否被新法替代？是否有溯及力问题？管辖层级与地域是否匹配？
    任一不通过 → 该引用降级为"待核实"，结论置信度下调。

闸⑤ 交付前 · 人审清单
    高价值结论生成"人审复核清单"：逐条列出需人工点开核验的引用与事实，按重要性排序。

成本分布：闸①②③ 可全自动、成本极低，拦约 90% 显性幻觉；
         闸④ 半自动（依赖法条库元数据质量）；闸⑤ 人工，仅用于高价值结论。
```

## 三、抗辩穷尽树（第六股）

```
                      ┌── 权利障碍抗辩：主体不适格 / 行为能力 / 内容违法 / 形式瑕疵 /
                      │                违反强制性规定 / 公序良俗
                      ├── 权利消灭抗辩：已履行 / 已免除 / 已抵销 / 已解除 / 混同 / 免除
       抗辩穷尽入口 ──┼── 权利阻止抗辩：时效 / 除斥期间 / 同时履行 / 先诉抗辩 /
                      │                不安抗辩 / 条件未成就
                      ├── 证据抗辩：    举证不足 / 证据能力 / 证明力弱 / 推定不利 /
                      │                自认反悔 / 鉴定缺失
                      └── 程序抗辩：    管辖异议 / 主体不适 / 前置程序 / 期间瑕疵 /
                                       送达瑕疵 / 形式欠缺

两条补充路径（防树上没有的漏掉）：
  P1【例外回溯】逐条读法条但书/除外条款/司法解释的限缩与扩张 → 每条但书 = 一条现成抗辩
  P2【事实反查】对已证事实表逐项问"若该事实不成立/相反，请求权是否动摇？" → 是则该事实是攻击点
```

**每条抗辩必填**：类型 + 规范依据（四元组）+ 支撑事实编号 + 强度（强/中/弱）+ 影响要件 A_。
**强度评分**：强 = 有明确规范 + 已证事实支撑；中 = 有规范但事实待证 / 或已证事实 + 解释性规范；弱 = 仅解释性主张。

## 四、7 条冲突解决优先级规则（第七股，结构化注入）

```
① 强制性规定 > 任意性规定
② 特别法 > 一般法
③ 上位法 > 下位法
④ 新法 > 旧法（注意从旧兼从轻等例外）
⑤ 有证据支撑 > 无证据支撑
⑥ 举证方未完成举证 → 该方承担不利后果
⑦ 格式条款解释存疑 → 作不利于提供方之解释
```

**每个冲突点必须**：填全天平两侧（事实/规范/证明标准/举证方/举证是否完成）+ 写明命中的规则编号。禁止"综合判断"式跳过。

## 五、事实分层四态标记（第三股）

| 标记 | 判定标准 | 后续可用方式 |
|---|---|---|
| **F** 已证事实 | 有书证/物证/生效文书/双方无争议陈述 | 可直接作为要件支撑 |
| **S** 单方陈述 | 仅一方主张、无独立证据 | 只能作为"主张"引用，须标陈述方 |
| **U** 存疑事实 | 证据矛盾/缺失/无法核实 | 进入存疑清单，不得作支撑 |
| **E** 排除项 | 与争议无法律关联 | 登记排除理由 |

**自动检测规则**：含"据…称 / 原告主张 / 被告陈述 / 据其回忆 / 据…所述"且无独立证据 → 强制标 S，禁止升级为 F。
**反向检测**：标 F 但检索不到证据来源 → 回退重判。

## 六、四态判定符号（第五股）

```
✓ 成立      —— 有已证事实 + 有效法条，双向齐备
◐ 部分成立  —— 要件可拆分，部分子项满足（须写明哪部分）
✗ 不成立    —— 事实缺失或法条不适用（须写明原因）
? 存疑      —— 依赖未证事实/有争议解释（须写明缺什么证据）
```

**禁止二态（成立/不成立）**。"存疑"这一中间态是防止模型被迫二选一的关键设计——给它合法的"不选"出口。

## 七、推理轨的机器可读约定（脚本解析用）

> 为让 check_redlines.py / check_dod.py 可自动校验，推理轨必须遵守以下约定。
> 行文轨不遵守（并须确保这些符号不外泄）。

```
【分段标题】  ## 第一段 · 破题  … ## 第八段 · 束股   （或 "第N段/第N股 · 名"）
【要件编号】  A1 A2 …（第四股清单、第五股判定使用同一编号集合）
【判定行】    行内含 "A<编号>" 且含四态符号之一 (✓ ◐ ✗ ?)
【抗辩编号】  D1 D2 …；漏洞 V1 V2 …；冲突点 C1 C2 …
【引用四元组】 [条文号][原文片段][来源标识][效力核验时间]
              亦接受标签式：条文号=…｜原文=…｜来源=…｜核验时间=…
              "未检索到"/"待核验" 视为合法占位（计 P1 提示，不计失败）
【覆盖自检】  出现 "要件清单条目数" "判定条目数" 两个数值
【三清单】    出现 "存疑清单" "适用边界" "排除项"（或"排除清单"）三个节
【结论】      第八股结论须含 "倾向于" 且含 "若"…"则"（条件式）
```

## 八、高频红线违规速查（33 条精简）

```
【法条】凭记忆出条文 / 引用已废止条文 / 忽略溯及力 / 跨法域混用 /
       层级错配 / 引用无法回溯 / 用司法解释代替原文
【事实】单方陈述当已证事实★最高频 / 保守过度有书证也标存疑 / 分层段就评价 /
       忽略材料来源偏向 / 论证中补事实
【要件】清单不封闭 / 提前单选规范 / 要件与抗辩混淆 / 消极事实判"不成立" / 不写举证责任
【论证】默认成立 / 二态判定 / 跳过推理直奔结论 / 责任形式混淆（有债权即自力实现）
【对抗】抗辩只列一两条 / 抗辩无依据 / 抗辩被正向锚定 / 抗辩写成"反驳结论"而非"攻击要件"
【权衡】用直觉代替规则序列 / 忽略举证责任 / 强行消除存疑 / 给无条件结论
【表达】绝对化表述 / 边界缺失 / 存疑折叠进脚注 / 补强建议空泛 / 给确定数值
【行文】机械符号（A1/✓/C1）外泄到正文
```
